三、特色功能
ProofCode 的核心思路是
1. 自主实现 Agent 运行流程
   项目不依赖现成的 Agent 框架，而是自行实现模型请求、工具调用解析、上下文组织、异常处理、执行循环和结束判断。这样既能了解 Coding Agent 的具体运行过程，也便于根据代码任务加入证据检查、版本更新和验证要求。
2. 提供受控的本地开发工具
   Agent 可以浏览目录、读取和搜索文件、修改代码、应用补丁、查看 Git 差异以及执行测试命令。系统会限制工具的访问路径、运行时间和输出长度，重要操作需要用户确认，在保证功能完整的同时提高执行过程的可控性。
3. 基于代码版本管理执行证据
   这是 ProofCode 的特色设计。文件读取、代码修改和命令执行都会形成带版本信息的证据。当文件发生变化时，项目 revision 随之更新，依赖旧版本得到的分析和测试结果会被标记为失效。只有当前版本通过项目级验证，Agent 才能报告任务完成。
4. 面向跨文件任务的工作记忆
   该部分吸收了 CodePlan 根据仓库状态和验证结果持续规划修改的思路。系统记录当前目标、已有发现、限制条件和下一步，并将这些内容与具体文件或命令结果关联。如果相关依赖发生变化，对应结论会自动过期，Agent 需要重新读取或验证。
5. L1—L4 分层记忆
   该结构主要参考 GenericAgent。L1 保存简短索引，L2 保存当前项目中经过确认的事实，L3 保存可以跨项目复用的操作流程和 Python Skill，L4 保存完整会话与工具执行记录。Agent 先通过索引定位信息，再按需读取具体内容，避免将全部历史记录放入上下文。
6. 经过验证的经验复用
   在 GenericAgent 记忆提交思路的基础上，ProofCode 加入了适用于代码任务的验证要求。Agent 可以从成功任务中总结操作流程或 Python Skill，但程序会复核其来源、代码内容、项目版本和测试结果。只有这些条件均满足时，经验才会写入全局 L3，供后续项目调用。
7. 长期记忆写入管理
   模型只能提出记忆候选，不能直接修改长期记忆。任务成功后，Runtime 会检查候选内容是否有执行证据支持、当前版本是否通过验证，以及是否适合长期保存，再决定写入项目记忆还是全局记忆，从而降低错误信息被长期保留的可能。
8. 测试反馈与执行审计
   项目借鉴 VRpilot 利用编译、测试和静态检查结果推动代码修复的方式，同时记录模型调用、工具执行、版本变化、验证结果和停止原因。系统还会识别重复读取、重复测试等行为，提醒 Agent 优先使用已有证据，使整个修改过程更容易检查和复现。
